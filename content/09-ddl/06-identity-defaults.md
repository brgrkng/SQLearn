## Generating keys: identity columns

Most tables use a **surrogate key**: a meaningless number the database hands out. The modern, standard way is an **identity column**:

```sql
CREATE TABLE authors (
  author_id int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name      text NOT NULL
);

INSERT INTO authors (name) VALUES ('Ada'), ('Grace');
SELECT * FROM authors;
```

- `GENERATED ALWAYS` rejects explicit values unless you write `OVERRIDING SYSTEM VALUE`. That protects you from accidentally inserting ids that later collide.
- `GENERATED BY DEFAULT` generates a value only when you don't supply one.

```sql error
INSERT INTO authors (author_id, name) VALUES (99, 'Linus');
```

Behind the scenes an identity column uses a **sequence**, a counter object. Sequences never roll back: if a transaction that took id 3 is rolled back, 3 is skipped. **Gaps in ids are normal.** Don't design anything that relies on ids being consecutive.

You'll still see the older `serial` / `bigserial` pseudo-types in existing schemas. They work, but identity columns are standard SQL and have fewer surprises with permissions and copying tables.

## Defaults

`DEFAULT expr` fills in a column you leave out. The expression is evaluated at insert time:

```sql
CREATE TABLE tickets (
  ticket_id  int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  subject    text NOT NULL,
  status     text NOT NULL DEFAULT 'open',
  opened_at  timestamptz NOT NULL DEFAULT now(),
  public_id  uuid NOT NULL DEFAULT gen_random_uuid()
);

INSERT INTO tickets (subject) VALUES ('Printer on fire');
SELECT ticket_id, subject, status, opened_at IS NOT NULL AS has_time, length(public_id::text) AS uuid_len FROM tickets;
```

A `uuid` default like `gen_random_uuid()` is useful when ids are created outside the database, or must not reveal how many rows exist.

## Generated columns

A **generated column** is computed from other columns of the same row and kept up to date automatically:

```sql
CREATE TABLE order_lines (
  line_id    int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  quantity   int NOT NULL,
  unit_price numeric(10,2) NOT NULL,
  line_total numeric(12,2) GENERATED ALWAYS AS (quantity * unit_price) STORED
);

INSERT INTO order_lines (quantity, unit_price) VALUES (3, 9.99);
UPDATE order_lines SET quantity = 4;
SELECT * FROM order_lines;
```

The expression may only use the row's own columns and *immutable* functions (no `now()`, no subqueries), and you can't write to the column directly. Use generated columns for values that are derived but expensive or awkward to recompute in every query, or that you want to index.

> **Dialect note.** Identity columns exist in SQL Server (`IDENTITY(1,1)`), Oracle 12c+ and Db2. MySQL uses `AUTO_INCREMENT`. Generated columns exist in MySQL (`VIRTUAL` or `STORED`), SQL Server (computed columns) and Oracle (virtual columns). PostgreSQL 18 also supports `VIRTUAL` generated columns, computed on read.
